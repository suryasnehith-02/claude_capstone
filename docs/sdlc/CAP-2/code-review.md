### 4.4 Persistence and concurrency design (by reading)
- Lock before transaction: `TaskService.write` (`TaskService.java:125-132`) takes the fair `ReentrantLock` (line 44) and only then calls `TransactionTemplate.execute`; the lock is released in `finally` after the commit or rollback. No `@Transactional` in main code (Grep of `M/`: only `TransactionTemplate`). Reads (`list`, `get`) take no lock and no transaction.
- One pooled connection: exactly one `HikariDataSource` (`PersistenceConfig.java:42-45`), pool 1, `minimumIdle` 1, `connectionTimeout` 5,000 ms (`:74-80`); one `DataSourceTransactionManager`, `TransactionTemplate` and `JdbcClient` built from it (`:47-60`); no `spring.datasource.*` key in `application.properties`.
- Durable settings: `SQLiteConfig` journal mode (DELETE default), `synchronous=FULL` (not configurable, `TodoProperties.java:26`), busy timeout 5,000 ms (`PersistenceConfig.java:67-70`); read back at startup, startup fails on a difference (`SchemaInitializer.java:97-109`); schema version check (`:78-84`).
- Boot SQL-init: disabled by `spring.sql.init.mode=never` (`application.properties:24`, round 2); `SchemaInitializer` is the only schema path (C10).
- Render before commit (D-23): render runs inside the transaction callback after the write (`TaskService.java:59-60,138-144`).
- Rejected requests change nothing: P1-P6 are before any repository call (4.2); TODO_NOT_FOUND on PUT/PATCH/DELETE throws inside the transaction, so it rolls back.
- No deadlock path found: a writer holds the lock then waits for the connection; a reader holds the connection without the lock and needs nothing else.

### 4.5 Performance (design review by reading only; nothing run, IMP-6)
- GET list: one indexed query `ORDER BY created_at DESC, seq DESC` with a matching index; one row mapper; one `JsonGenerator` into a byte array. At 1,000 tasks of maximal size the body is about 2.4 MB and is held twice briefly (`ByteArrayOutputStream` plus `toByteArray`); acceptable for one user.
- GET/PUT/PATCH/DELETE by id: lookups on the `UNIQUE` index of `id`; at most two statements per mutation; no N+1.
- P5 parses the body twice (token scan, then `readTree`), each at most 65,536 characters: negligible.
- Writes: 2-3 fsyncs per commit plus per-commit journal create/delete under `journal_mode=DELETE` (R-10); reads queue behind a write on the single connection. Whether p95 at or under 500 ms holds on the target Windows host is **unverified** (section 3.1).
- Round 2: the abort checks are two `instanceof` tests and one attribute read. The developer's one-off 157.6 s run of `ErrorLogContentContractTest` (run 79, not reproduced in runs 80 and 83) is unexplained (report item 5); not a product-code finding, but Stage 7 should note it if it recurs.

### 4.6 Security and input-validation notes (by reading)
- Response bodies: every error body comes from `ApiResponses.fixedError` or `error(code, details)`; no exception text, URI or attribute is echoed (`ApiGatewayFilter.java:261-275`, `FallbackErrorController.java:68-71`, `ApiExceptionHandler.java:90-97`). Tomcat `ErrorReportValve` report and server info off (`TomcatConfig.java:46-68`); `spring.web.error.include-*` never, whitelabel off, ProblemDetail off (`application.properties:12-15`).
- Logging: only request id, letters-only method token, route template and exception class/stack (`ApiGatewayFilter.java:293-302`); `RouteMatch.toString` and `RawBody.toString` hide client data. Exception messages inside logged stack traces are not scrubbed; round 2 adds a real-engine check that the SQLite constraint message carries no bound value (`ErrorLogContentContractTest`), and no main-code exception message concatenates a request value (checked by reading every `throw new` in `M/` in round 1; round 2 adds no `throw new` in main code).
- SQL: every statement in `SqliteTaskRepository.java:39-74` uses `?` parameters; the only concatenations are compile-time constants (`COLUMNS`, `SCHEMA_VERSION` at `SchemaInitializer.java:93`).
- TRACE: `allowTrace=true` (`TomcatConfig.java:33`) is safe only because the gateway always rejects TRACE at P1; the gateway is the single control (it covers `/*` for REQUEST and ERROR).
- Native library: sqlite-jdbc extracts its native library to the temp directory at startup (architecture R-10); `--enable-native-access=ALL-UNNAMED` is passed in the POM and README. Not a code defect; listed for the audit in section 5.
- Body limit: Content-Length checked before reading, then a hard capped read (`BodyGate.java:49-56`); the Jackson document, string and name limits equal the cap, so they never trigger first (`JsonConfig.java:30-35`).
- Round 2, `CLIENT_ABORT_ATTRIBUTE`: a servlet request attribute; HTTP clients cannot set request attributes (only server code in the same request can), the name is class-qualified (`ApiGatewayFilter.java:79`) and the value must be `Boolean.TRUE` (`:324`). It changes only the log level of the error controller's 500, never the status or the body. No security regression found.
